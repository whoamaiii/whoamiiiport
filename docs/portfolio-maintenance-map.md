# Portfolio Maintenance Map

This document captures the remaining cleanup and maintenance risks discovered
during the portfolio hardening pass. It is meant to preserve the useful
engineering lessons without treating every historical experiment as active
runtime risk.

## Summary

The public site is now much healthier than the source tree. Runtime image
delivery uses optimized WebP assets and contract tests, but the repository still
contains raw creative-process residue: large source assets, duplicated media,
old visual QA screenshots, overlapping docs, and custom shader/glass systems
that need careful validation.

## Priority Cleanup Areas

### 1. Source Asset Bloat

**Status:** Current
**Risk:** Repository size and maintenance drag

`src/assets` is much larger than the generated `public/images` output. The live
site uses optimized assets, but the repo still carries large raw originals.

Recommended cleanup:

- Keep only source images required by `scripts/optimize-images.js`.
- Move archival originals to external storage or an ignored local archive.
- Keep public runtime assets generated and tested through the image contract.

### 2. Duplicate Asset Sources

**Status:** Current
**Risk:** Source-of-truth confusion

Some artwork files appear both directly under `src/assets` and in
`src/assets/first10`.

Recommended cleanup:

- Keep one canonical original per artwork.
- Delete duplicates only after confirming no app code or optimizer config
  references them.
- Use slug-style filenames for future source assets.

### 3. Local Screenshot Artifacts

**Status:** Mostly contained
**Risk:** Git noise and review confusion

`analysis/` contains many local visual review screenshots. The repo now ignores
local image and HTML artifacts there while keeping markdown notes trackable.

Recommended cleanup:

- Keep only curated final comparison images when intentionally documenting a
  design decision.
- Let temporary screenshots stay ignored.
- Prefer concise markdown notes for durable visual decisions.

### 4. Generated Output

**Status:** Contained if ignored
**Risk:** Stale build artifacts being mistaken for source

`dist/` is generated by Vite and should not be treated as source unless the
deployment flow explicitly requires it.

Recommended cleanup:

- Keep generated output ignored for normal development.
- Validate deploy builds from source with `npm run build`.

### 5. Custom Shader And Glass Systems

**Status:** Active
**Risk:** Mobile performance, fallback behavior, and browser compatibility

The hero title and section headings now use sophisticated canvas/WebGL rendering
with fallback paths. This is part of the visual identity, but it is also one of
the easiest areas to regress.

Recommended guardrails:

- Treat unsupported WebGL as a normal fallback path.
- Keep reduced-motion exits before expensive animation or observer setup.
- Validate changes on the mobile `390x844` Playwright project.
- Avoid adding new shader systems without a visible payoff and fallback plan.

### 6. Motion At The App Root

**Status:** Current, partly controlled
**Risk:** Mobile devices paying for desktop-only effects

`src/App.tsx` owns multiple scroll and pointer-driven motion values. Current
gates help, but the logic should stay carefully bounded.

Recommended cleanup:

- Keep pointer effects gated by device capability and viewport.
- Consider moving background interaction logic into a dedicated hook or closer
  to `PsychedelicBackground`.
- Add regression coverage if the root animation model expands.

### 7. Media Contract Drift

**Status:** Improved
**Risk:** Missing generated files, dead slugs, and stale video paths

The repo now has a clearer image/media contract through `src/utils/images.ts`,
`src/utils/media.ts`, `scripts/optimize-images.js`, and
`tests/image-contract.test.ts`.

Recommended rule:

Any future image or video change should update all related pieces together:

- source file
- optimizer config
- runtime manifest/helper
- generated public asset
- contract test
- docs when behavior changes

### 8. Documentation Overlap

**Status:** Current
**Risk:** Conflicting guidance and slower onboarding

The repo has several root docs and focused docs under `docs/`. This is useful
only if each document has a clear purpose.

Recommended cleanup:

- Keep `README.md`, `AGENTS.md`, `CLAUDE.md`, and focused docs in `docs/`.
- Archive or delete old broad summaries after their durable decisions are
  captured elsewhere.
- Prefer one canonical location per rule or architectural decision.

## Maintenance Rules To Keep

- Keep the portfolio mobile-first until that direction is explicitly changed.
- Keep `desktop-chromium` and `mobile-390` Playwright projects passing.
- Keep gallery video support scoped through `GALLERY_VIDEOS`.
- Do not revive the removed hero overlay video without a deliberate new scope.
- Keep local QA screenshots outside tracked source unless curated intentionally.
- Separate runtime performance risk from repository/source-size bloat.

## Validation Stack

Use this stack for release-level confidence:

1. `npm run optimize-images`
2. `npm run test -- tests/image-contract.test.ts`
3. `npm run check`
4. `npm run test:e2e`
5. `npm audit --audit-level=moderate`
6. Mobile sanity at `390x844`

## Bottom Line

The runtime is now much more disciplined than the workspace history. The main
remaining work is repo hygiene: reduce raw asset bloat, keep visual QA artifacts
curated, and avoid expanding the custom rendering stack without matching mobile
validation.
